# Technical English Review

## Purpose

Evaluate technical English to ensure that it communicates technical concepts accurately, clearly, precisely, and efficiently while preserving established domain terminology and the author's intended meaning.

## Procedure

1. Determine the technical context, intended meaning, audience, and purpose.
2. Check grammatical and syntactic correctness.
3. Check technical terminology for accuracy and consistency.
4. Check whether technical terms are used with their conventional meaning.
5. Check clarity, precision, and potential ambiguity.
6. Check whether the wording accurately represents technical relationships, behavior, constraints, or conditions.
7. Check consistency in terminology, capitalization, naming, and references when applicable.
8. Check naturalness and readability without compromising technical precision.
9. Check conciseness and remove unnecessary or redundant wording.
10. Identify only the most valuable improvements.
11. Provide a revised version that preserves the technical meaning and terminology.
12. Explain significant changes briefly and identify reusable technical language patterns when useful.

## Prioritization

Prioritize issues in this order:

1. Wording that changes, obscures, or misrepresents technical meaning.
2. Incorrect or ambiguous technical terminology.
3. Statements that could lead to an incorrect technical interpretation.
4. Inconsistent terminology or references.
5. Grammatical errors that affect clarity or professionalism.
6. Unclear or unnecessarily complex sentence structures.
7. Unnecessary verbosity or repetition.
8. Minor stylistic improvements.

Do not replace established technical terminology with more common wording when doing so could reduce technical accuracy or change the intended meaning.

## Feedback Requirements

- Be concise, precise, and technically accurate.
- Preserve established technical terminology when it is correct.
- Distinguish language problems from technical-content problems.
- Do not assume that a technically unusual expression is incorrect English.
- Do not alter technical meaning while improving grammar or style.
- Prefer explicit and unambiguous wording when technical precision matters.
- Preserve code identifiers, API names, class names, method names, configuration
  keys, and other literal technical references.
- Avoid unnecessary formalization or simplification of technical language.
- Identify potential ambiguity when different readers could reasonably interpret
  the statement differently.
- Explain significant terminology or wording changes briefly.

## Output

Use this structure when applicable:

**Improved version:**  
<revised technical text>

**Feedback:**
- **<original expression> → <improved expression>** — <brief explanation>
- **<original expression> → <improved expression>** — <brief explanation>

**Technical pattern:**  
<short reusable technical language pattern>

Omit sections that do not provide meaningful value.
